01 / Read the sheet

Color is the proof. Grayscale is the ink.

The first pair shows the full source composition and a simulated overprint. Each grayscale thumbnail below describes one physical ink pass: black means full ink; white means none. Its label and swatch say which ink that pass uses.

02 / Physical scale

Pixels, millimeters and screens.

DPI sets physical size

At 300 DPI, 1,200 pixels span 101.6 mm. Keeping the same pixels and increasing DPI makes a smaller print; it does not invent detail.

width mm = pixels × 25.4 / DPI

LPI sets screen spacing

A 50 LPI screen at 300 DPI has a 6 pixel pitch. At 600 DPI it needs 12 pixels to preserve the same physical spacing.

pitch pixels = DPI / LPI

Use the effective values in the recipe. Raster screen limits may change the requested frequency. A solid or continuous-tone pass has no Stiprā screen frequency; your physical printer may still apply its own screening.

03 / Make it again

Keep the original and the recipe together.

A print package contains original source bytes, aligned grayscale plates, a proof, reports, normalized ink and screen recipes, and a manifest of hashes and settings. The PDF also embeds recipe attachments; some browser viewers hide them, so use a PDF reader with an attachments panel or use the ZIP.

  1. Keep your authorized original. Check its SHA-256 against the package manifest before replaying.
  2. Use the same Stiprā code revision and recorded runtime/dependency versions.
  3. Read recipe/inks.json and recipe/screens.json. Replay those effective recipes rather than assuming a future named style has the same defaults.
  4. Set the recorded DPI, stock and marks explicitly. Compare output hashes in the same environment; decoder and color-profile differences can change pixels across runtimes.
git clone https://github.com/yigit-denktas/stipra.git
cd stipra
# Check out the code revision used by your original job.
npm install --no-audit --no-fund
node bin/stipra.js package \
  --input /private/original.jpg \
  --config /private/package/recipe/inks.json \
  --screen /private/package/recipe/screens.json \
  --dpi 300 --paper recipe --marks-mm 0 \
  --expected-sha256 YOUR_ORIGINAL_SHA256 \
  --out /private/replayed.zip

Replace paths, SHA-256, DPI and marks with the recorded job values. The command creates a new output and refuses to overwrite an existing package. Exact recipes reproduce ink settings; report presentation may change between code revisions.

04 / Inspect before printing

Make each plate earn its place.

Look at both the proof and the individual masks at the intended print size. Check small type, thin edges, highlights, shadows and the detail your image depends on. Toggle inks to understand what each one contributes.

Coverage and overlap diagnostics are measurements, not artistic scores or universal printer safety limits. A sparse third pass may carry an essential detail, or it may be unnecessary. A dense key may preserve form, or hide it. Decide from the artwork and the actual printing setup.

RGB ink colors, multiply blending and simulated paper are uncalibrated previews. Physical ink spread, drying, fluorescent pigments, stock and registration need a real print test.

05 / Your artwork

Local work stays local.

The browser studio processes imported artwork on your device. Opening this public guide or its QR code does not upload the photograph or recover a private job. Reproduction still requires your authorized original and saved recipes.

Keep photographs and image-bearing reports private unless you have permission to redistribute them. Public examples on this page are authored schematics, not owner photo fixtures.
