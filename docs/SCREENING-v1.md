# Screening · deterministic ink-mask textures (v1)

**Implemented for imported-image raster masks:** [#5](https://github.com/yigit-denktas/stipra/issues/5). An independently written, MIT-licensed raster screen engine applies dot, line, paper knockout, hybrid and registration settings to the **real physical ink coverage masks** generated by [separation v1](IMAGE-SEPARATION-v1.md). All plate files keep the same pixel grid and the original image is never modified.

This is **not** the print shop's calibrated RIP, spectral Riso simulation, press-specific halftone angles, spot-ink mixing profile, measured dot gain or a guarantee of suitability for a physical stencil.

## Try it

Serve the repo locally and open [the separation lab](../examples/separation-lab/index.html) to change screening modes, global pitch/angle/seed, and per-ink angles and registration offsets. Download monochrome plates, the ink separation recipe, and a distinct screen recipe.

```sh
npm install
node bin/stipra.js separate \
  --input artwork.png \
  --config examples/recipes/spot-photo.json \
  --screen examples/recipes/screens-spot.json \
  --out out/screened-two-ink

# Four CMYK channels (separate screening angles per pass)
node bin/stipra.js separate \
  --input artwork.png \
  --config examples/recipes/cmyk-photo.json \
  --screen examples/recipes/screens-cmyk.json \
  --out out/screened-cmyk
```

These commands generate the **existing full-frame continuous-tone plate PNGs** and additional `screened-<ink-id>-plate.png`, `screened-preview.png` and `screen-recipe.normalized.json`. `separation-manifest.json` contains per-plate screen settings, post-screen coverage estimates and original-source provenance. The CLI refuses to overwrite files, including source inputs and recipe files.

## Recipe

```json
{
  "version": 1,
  "seed": 142,
  "default": {
    "mode": "dots",
    "pitch": 12,
    "angle": 30,
    "dotScale": 1,
    "jitter": 0.03,
    "solidThreshold": 0.9,
    "registration": {"x": 0, "y": 0, "rotate": 0}
  },
  "plates": {
    "blue": {"mode": "hybrid", "angle": 45, "solidThreshold": 0.85},
    "coral": {"mode": "reverse", "angle": -20}
  }
}
```

- `version`: fixed at 1. `seed`: integer 0–4,294,967,295. Identical input bytes, recipes and compatible runtime implementations give byte-identical output masks.
- `mode`: `solid` preserves continuous coverage unchanged; `dots` prints clustered positive cells; `reverse` fills a cell but punches paper-colored holes; `lines` makes parallel bands; `hybrid` preserves original strong marks above `solidThreshold` but screens mid-tones with dots; `paper` yields zero ink for that selected plate. The substrate itself is **never** an ink.
- `pitch`: dot-cell period in **output pixels** (4–128), not lines per physical inch. `angle`: screen rotation in degrees (-180..180). `dotScale` (0.1..2): radial dot/line scale. `jitter` (0..0.3): stable per-cell shifts based on the seed. `solidThreshold` (0.01..1): unscreened high-coverage exception for hybrid.
- `registration`: signed x/y shift in pixels (±50) and rotation (±15 degrees) applied **only to the ink pass after screening**, not to the source image or shared canvas. Content moved off the edge is clipped, not wrapped or resized.
- `plates`: optional named, strict per-ink overrides. Unknown plate names and unknown parameter fields are rejected. Omitted plates inherit global settings, including registration.

Raster screening works by averaging the original 0..255 coverage within rotated cells and creating controlled binary ink geometry inside each cell; **zero-coverage source pixels stay clear**, preventing dots from growing outside the source's intended support. At 100% with zero jitter the ink fills the cell. Partial tone and registration are approximations; do not expect linear perceived density or physically measured printable dot gain.

The ink-color composited proof is produced from the **screened grayscale masks**, never by tinting the unscreened source. The original 8-bit unscreened coverage is retained in separate output files for comparison.

## Code contract

```js
const Sep = require('./src/separation.js');
const Screen = require('./src/screening.js');
const unscreened = Sep.separate({width, height, rgba}, inkRecipe);
const screened = Screen.apply(unscreened, screenRecipe);
screened.masks[0].coverage;   // Uint8Array(width * height), 0 paper .. 255 full ink
screened.preview;             // RGBA colored overprint simulation, same width and height
screened.stats.inks;          // coverage and number of inked pixels
```

The raster and browser builds are the **same UMD module**, not two independent ports. CI exercises geometry modes, deterministic seeds, input transparency, preset CMYK angles, per-plate registration, boundary clipping, pure Node/browser parity, the CLI's actual full-resolution file exports, and Chromium controls.
