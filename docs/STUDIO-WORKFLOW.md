# Studio workflow acceptance

The image-input workspace implements import → choose shared style → edit physical ink masks → inspect → export. It remains a local experimental printmaking tool; artistic approval, authored-layer import UI, machine profiles and physical press calibration are separate work.

Import PNG/JPEG/WebP or the supported geometric SVG subset, respecting the existing byte/pixel/color boundaries. Rejected files leave the previous separation intact. The UI shows loading and validation errors; no uploaded script is executed and no image processing request leaves the browser.

Choose a shared starting Style or a manual spot/CMYK recipe. To preserve current manual edits while exploring, open **Compare recipes**, choose **Candidate recipe**, then **Preview comparison**. The paired full proofs share source pixels, framing, current paper, DPI and seed. Candidate inks/screens belong to the selected recipe and effective LPI is shown. Comparison is computed on demand, not on every slider movement.

**Keep current** retains all edits and inspection state. **Use candidate** applies the exact displayed normalized recipe, retains the comparison paper, updates the style selectors/advanced controls and shows all inks. Exports use current settings until that explicit action. A mask/screen/paper/geometry edit, candidate change or new import clears the old preview; import-in-progress and invalid settings block adoption. Solo/mute and paper-only inspection do not alter the full comparison. The guide uses these same control names.

 Spot mode supports 2–8 physical inks; increasing the count preserves existing passes and adds explicitly editable tone-based passes. Paper stays outside the ink array. Per-ink source, threshold, strength and gamma edit actual continuous coverage; screening then creates real plates. Global and per-ink angles/pitch/mark scale, hybrid hold threshold, seed, jitter and proof registration use the same validated engine as the CLI. Shared Styles resolve physical LPI; manual pitch remains explicitly pixels, with effective LPI reported.

Each grayscale plate has an `Adjust [ink name]` button. It opens the matching ink disclosure, scrolls its summary into view and moves keyboard focus there; it does not change the recipe, solo/mute state or plate pixels. This works after shared-style changes, in CMYK and with eight manual inks, including when settings sit below the artwork on a phone.

Solo/mute and paper-only/transparent-substrate controls affect the inspection canvas only. Individual grayscale plates and package exports retain all configured inks. The full proof PNG also exports the complete configured treatment, not a transient solo view. `All inks` resets inspection. These controls use labeled checkboxes and pressed-state buttons; solo preserves keyboard focus. Native pixel zoom means one artwork pixel per CSS pixel, not calibrated physical print size. Fitted and native views preserve the original aspect and never change the source/plate grid.

Print geometry shows native trim in millimeters at the selected DPI, origin 0,0 and optional registration-mark border. No bleed or machine-safe area is invented. Marked masters add their border outside the common trim; unmarked masters retain exact native dimensions. The A4 PDF/HTML reports are inspection sheets, not resized print masters. Source/profile metadata, recipes, all passes, hashes and font notices travel in the ZIP; proof offsets remain outside production registration.

Browser acceptance uses actual dropped procedural artwork and checks color boundaries, real mask edits, solo/reset/paper/zoom, 8-ink setup, responsive layouts at 390/768/1024/1339/1440 pixels, accessible labels/disclosure/focus, plate-to-ink navigation with unchanged pixels and 44px touch targets, shared variants, export pixels/hashes/density/marked geometry and PDF recipe attachments. Existing alpha checks compare browser exports with Node and CLI. Processing stays under `connect-src 'none'`; local script/font loads are separately served app assets. No physical-print result is claimed.

The named-region forest demonstration also keeps its explicit `INK` lettering on a solid coral pass while screening the tree regions. This is an artist-authored distinction, not automatic text detection. The color-match baseline uses the same per-ink screen settings.
