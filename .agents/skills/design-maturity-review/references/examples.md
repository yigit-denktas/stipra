# Review examples

Stiprā-local companion reference, derived from the owner's uploaded Design Maturity Review v1.0.0 SKILL.md; the originally referenced document was not supplied. Use the original SKILL.md as authority. Do not attribute this material to the missing original reference.

Example 1: a release timeline looks clean but mislabels merged PRs as shipped. This is a source-of-truth failure, not merely a typography concern. Preserve the timeline, fix publication data and verify against a real release event.

Example 2: an intentional irregular ink registration motif improves product recognition without harming the reading order. Keep it; don't impose sterile alignment simply for consistency.

Example 3: tiny monospace issue identifiers dominate an onboarding surface. Move provenance one level deeper and test whether a newcomer can identify the current priorities and first meaningful action on a phone.

Counterexample: a screenshot looks polished, but import/export cannot be exercised. Mark software behavior unknown, not strong.
